# GUI

## Окна и левая панель Projects

Главное окно использует собственный заголовок с кнопками сворачивания, разворачивания и закрытия. Диалоги оформляются в общей безрамочной теме; настройки моделей открываются отдельной безрамочной панелью.

- Заголовок Projects расположен вверху; при отсутствии чатов пустая область имеет единый фон панели.
- Чаты группируются по пути проекта и сортируются по времени обновления. Сначала видны до пяти чатов проекта; `Show more` / `Show less` раскрывает или сворачивает остальные.
- Контекстное меню чата удаляет чат, меню проекта — все его чаты; перед удалением появляется подтверждение.
- При переключении сессии старый transcript не очищается заранее: он заменяется после получения новой истории.

## Настройка Session size

В настройках моделей слайдер Session size задаёт общий порог автосуммаризации: 10 000–256 000 токенов, шаг 2 000. Это порог контекста LLM, а не число сообщений в UI. Значение сохраняется в `.agent_state/config.json`; приоритет источников описан в [CONFIGURATION.md](./CONFIGURATION.md).

## Transcript

Streaming-ответы, tool cards с аргументами и результатами, summary-сообщения, статусные notice. Повторный префейс модели после выполнения инструментов подавляется с учётом нечёткого совпадения (fuzzy matching), чтобы избежать дублирования текста при минимальных расхождениях.

Карточка инструмента появляется, как только в потоковых аргументах закрыт его якорный аргумент: для файловых инструментов — полный непустой путь (`path`, а где применимо также `file_path`, `filepath`, `dir_path`), для `cli_exec` — команда, для поисковых инструментов — запрос или шаблон, и т. д. Остальные аргументы и начало выполнения не требуются. Незакрытая строка в сыром JSON не считается готовым значением. Для инструментов без известного якоря карточка появляется при первых непустых аргументах. При поступлении остальных аргументов и начале выполнения обновляется та же карточка, в том числе при позднем получении ID вызова.

При сбое потока, повторе запроса, смене API-ключа или остановке уже показанная незавершённая карточка закрывается как прерванная, а накопленные чанки сбрасываются, чтобы не смешиваться с новым вызовом. Если результат пришёл без существующей карточки, она создаётся принудительно.

Полная история переписки (`transcript_messages`) сохраняется в checkpoint отдельно от сжатого контекста модели: автосуммаризация удаляет старые сообщения только из контекста LLM, но не из истории чата в UI. Сессии, созданные до внедрения этой схемы, могли потерять старые сообщения при compaction — восстановить их автоматически нельзя.

## Длинная история

Изначально создаются виджеты последних `HISTORY_BATCH_SIZE` ходов (по умолчанию 10). Кнопка `Load earlier messages (N)` добавляет следующую порцию ранних ходов сверху. Во время загрузки она отключена и показывает `Loading earlier messages…`; позиция читаемого сообщения сохраняется при изменении высоты Markdown и карточек. Один ход включает сообщения и инструменты, а не равен одному `BaseMessage`.

Это отложенное создание UI-виджетов, а не постраничный запрос в checkpoint store: данные ранних ходов уже находятся в памяти UI. Параметр `HISTORY_BATCH_SIZE` не ограничивает сохраняемую историю и не меняет порог суммаризации.

## Индикатор автосуммаризации

Кольцо рядом с composer показывает заполнение контекста до порога автосуммаризации (`SESSION_SIZE`):

- Tooltip содержит только процент: `20% left until auto-summary.` (сколько осталось до автосуммаризации).
- При достижении порога: `Auto-summary will run on the next step.` — на следующем шаге агент проверит возможность суммаризации; политика может отложить её, если сжимать пока нечего.
- При `SESSION_SIZE=0` индикатор скрыт (автосуммаризация выключена).
- Дуга показывает использованную долю: синяя — обычный режим, янтарная — заполнено 85%+, зелёная — автосуммаризация готова к выполнению. Процент считается от `SESSION_SIZE` (например, `80000`), без учёта внутреннего soft-margin, который лишь защищает от преждевременного сжатия.

## CLI Output Widget

Для `cli_exec` вывод команды (stdout/stderr) отображается в реальном времени прямо в карточке инструмента, по мере поступления чанков. После завершения карточка автоматически сворачивается (с короткой задержкой для успешных команд). Команды с ненулевым exit code, использующие его как часть нормального протокола (`grep`, `rg`, `vulture`, `pytest`, `diff` и др.), не помечаются как ошибка — вывод возвращается с префиксом `Exit Code: N`.

## Composer

- Вставка файлов через `Add files…`, drag-and-drop или clipboard paste
- `@`-mention popup с файлами и директориями текущего workspace (обновляется динамически)
- Нормализация текста перед отправкой: `\r\n` → `\n`, удаление control-символов
- Лимит 10 000 символов на запрос с inline-предупреждением при усечении

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Enter` | Отправить сообщение |
| `Shift+Enter` | Новая строка |
| `Ctrl+N` | Новый чат |
| `Ctrl+B` | Показать / скрыть боковую панель |
| `Ctrl+I` | Показать / скрыть inspector-панель |
| `↑` / `↓` в пустом composer | История отправленных сообщений |
