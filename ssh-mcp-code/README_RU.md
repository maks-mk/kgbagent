# ssh-mcp

Сервер [Model Context Protocol](https://modelcontextprotocol.io) (stdio), который предоставляет MCP-клиентам возможности SSH-выполнения в стиле Bash, постоянные интерактивные сессии, чтение/редактирование/поиск удаленных файлов, передачу данных через SCP/rsync и проброс портов.

Сервер использует локальный клиент OpenSSH (`ssh`, `scp`) и `rsync`, поэтому он переиспользует ваши существующие конфигурации SSH, ключи и агентов. Работает на POSIX и Windows (интерактивные сессии на Windows используют ConPTY через `pywinpty`).

## Установка

```bash
pip install .
```

Для работы интерактивных сессий на Windows дополнительно требуется `pywinpty` (устанавливается автоматически благодаря маркеру зависимости `platform_system == 'Windows'`).

Инструмент `ssh_sync` вызывает локальный клиент `rsync`, который по умолчанию отсутствует в Windows. Установите его (через MSYS2, Git for Windows, WSL) и добавьте в `PATH`, либо используйте `ssh_scp` для разовых передач.

## Запуск

Сервер использует протокол JSON-RPC 2.0 через stdio:

```bash
python -m ssh_mcp
# или, после установки, через консольный скрипт:
ssh-mcp
```

Укажите эту команду в настройках вашего MCP-клиента с использованием транспорта `stdio`.

## Конфигурация

Сервер можно настроить с помощью переменных окружения:

- `SSH_MCP_MAX_CONCURRENCY`: Количество рабочих потоков для вызовов инструментов (по умолчанию: `4`). Установите `1` для строго последовательного выполнения.
- `SSH_MCP_LOCAL_ROOT`: (См. раздел [Локальные пути](#локальные-пути))

## Портативная сборка (Windows)

Чтобы собрать автономный исполняемый файл, который не требует установки Python на целевой машине:

```powershell
.\build.bat
```

Этот скрипт использует `PyInstaller` для создания `dist/ssh-mcp.exe`. Сборка включает `winpty` и другие необходимые зависимости для работы интерактивных PTY-сессий в Windows.

## Локальные пути

Инструменты `ssh_scp` и `ssh_sync` перемещают файлы между удаленным хостом и *локальной* машиной, поэтому им нужно знать, какой каталог считать базовым для относительных путей. Любой относительный локальный путь (включая `.`) разрешается относительно **локального корня**:

1. `SSH_MCP_LOCAL_ROOT`, если эта переменная окружения установлена и указывает на существующий каталог, иначе
2. рабочая директория процесса сервера, которую MCP-клиенты обычно устанавливают равной директории с файлом `mcp.json` — обычно это *не* тот проект, над которым вы работаете.

Результат работы инструмента всегда содержит `local_root` и `resolved_local_paths`, чтобы было видно, какие именно локальные пути были использованы. В случае сомнений используйте абсолютные пути. Для фиксации корня можно использовать ключи `env` и `cwd` в конфигурации stdio-сервера:

```json
{
  "mcpServers": {
    "ssh": {
      "command": "./ssh-mcp/ssh-mcp.exe",
      "cwd": "D:/work/my-project",
      "env": { "SSH_MCP_LOCAL_ROOT": "D:/work/my-project" }
    }
  }
}
```

В качестве меры безопасности относительный локальный *источник*, который разрешается в сам локальный корень (или в одного из его родителей), отклоняется с ошибкой валидации, чтобы избежать случайного копирования всей директории запуска агента; если вам действительно нужен этот каталог, передайте абсолютный путь. Относительные пути к `identity_file` и `known_hosts_file` следуют тому же правилу, поэтому `cwd` определяет место их поиска, если `SSH_MCP_LOCAL_ROOT` не установлен.

## Инструменты

- `ssh_exec` — запуск разовой удаленной команды.
- `ssh_start_session` / `ssh_ensure_session` / `ssh_read_session` /
  `ssh_write_session` / `ssh_stop_session` / `ssh_list_sessions` — постоянные интерактивные сессии на базе PTY.
- `ssh_view` / `ssh_create` / `ssh_edit` / `ssh_grep` / `ssh_glob` — чтение/создание/редактирование/поиск удаленных файлов.
- `ssh_scp` / `ssh_sync` — копирование и инкрементальная синхронизация файлов (`ssh_sync` требует наличия `rsync` в `PATH`).
- `ssh_forward` / `ssh_list_forwards` / `ssh_stop_forward` — проброс SSH-портов.

## Состояние и постоянство

Сервер предназначен для работы в качестве долгоживущего процесса. Интерактивные сессии и пробросы портов хранятся в памяти в течение жизненного цикла сервера. При использовании MCP-клиента, поддерживающего постоянные stdio-сессии, SSH-соединения остаются открытыми между вызовами инструментов, что позволяет избежать повторных рукопожатий (handshakes).

Вызовы инструментов выполняются параллельно в пуле потоков, поэтому длительная команда не будет блокировать другие запросы. Ответы возвращаются по мере их готовности (порядок может отличаться от порядка запросов). Для предотвращения вечных зависаний установлены таймауты по умолчанию: 60 секунд для `ssh_exec` и 120 секунд для удаленных скриптов.

## Заметки по безопасности

Параметры `extra_ssh_args` и `target` проверяются, чтобы отклонить опции и флаги SSH, которые могли бы запустить команды или загрузить библиотеки на локальной машине, или перенаправить транспорт:

- `target` (хост/назначение) не должен начинаться с дефиса (`-`), чтобы предотвратить инъекцию опций.
- Опции `-o`: `ProxyCommand`, `LocalCommand`, `PermitLocalCommand`,
  `LocalForward`, `RemoteForward`, `DynamicForward`, `KnownHostsCommand`,
  `PKCS11Provider`, `SecurityKeyProvider`.
- Короткие флаги: `-L`, `-R`, `-D`, `-W` (используйте инструмент `ssh_forward`) и
  `-F` (загрузка произвольного файла конфигурации ssh). Отклоняются как раздельные (`-L spec`), так и слитные (`-Lspec`) формы.

Вместо использования `extra_ssh_args` используйте выделенные параметры `port`, `identity_file`, `known_hosts_file` и `strict_host_key_checking`.

## Версии протокола

Поддерживаемые версии протокола MCP: `2025-06-18` (по умолчанию) и `2024-11-05`. Если клиент запрашивает неподдерживаемую версию, сервер согласовывает её в сторону понижения до поддерживаемой версии вместо того, чтобы просто вернуть неизвестную версию.
